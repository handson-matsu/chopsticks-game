# Chopsticks — 指先から、数学へ。

教育・数学研究向けの日本語静的Webアプリです。HTML / CSS / JavaScriptのみで動作し、外部ライブラリ・ビルドは不要です。ゲーム・解析は外部通信に依存せず、ページ読み込み時だけ共通GASアクセスカウンターへ送信します。

## 起動

リポジトリ直下で `python3 -m http.server 8000 --bind 127.0.0.1` を実行し、ブラウザで `http://127.0.0.1:8000/` を開きます。ES ModulesとWeb Workerを使用するため、file://で直接開かずHTTP経由で利用してください。

GitHub Pagesでは、このファイル一式をmainブランチのルートから配信できます。GitHubのSettings → Pagesで配信元を選択します。今回は公開設定、commit、pushは行っていません。

## 操作

設定でルール、n（2〜20）、両者の手数（1〜6）、各手の値、先手、人間の担当、対戦形式、CPU難易度を選びます。初期値はModuloで0〜n−1、Cutoffで0〜n。n・ルールの変更時は範囲外の値を上限まで切り下げ、表示にも反映します。両者の全手が0の設定は拒否します。片側のみ全手0なら開始時点で相手の勝利です。

自分の0以外の手を選択し、相手の0以外の手を選ぶと攻撃します。Bを上、Aを下に表示します。数字カード、計算のアニメーション、手番・勝利表示、棋譜、Undo、もう一度、新しいゲーム、設定への復帰に対応します。CPU対戦のUndoは人間の直前の操作前まで戻します。CPUが先手の初手のみを戻した場合、CPUが再び指します。

- Modulo：攻撃後は `(b+a) mod n`。
- Cutoff：`b+a <= n` なら合計、それ以外は0。
- 攻撃側の値は変化しません。分配・復活はなく、0は攻撃元にも対象にもなりません。
- Moduloで局面が循環しても対戦は継続します。

「局面を解析する」は対戦とは独立したモードです。現在の手番からの評価、全合法手（カードの位置を区別）、遷移後の局面、各手の評価、必勝手、完全解析の成否を表示します。

## 解析の意味・計算上限

状態キーはルール・n・手番と、両者それぞれのソート済み手の列です。UI上のカード順は維持します。

Cutoffはメモ化再帰で全子局面を評価します。順位関数 `Σ(v>0 ? n+1−v : 0)` が毎手必ず減少するため循環しません。Moduloは到達可能な状態グラフを構築し、終局から逆向きに勝ち・負けを伝播します。分類されずに残る状態が引き分け（双方が負けを回避できる無限プレイ）です。単に一度循環したことを引き分けの根拠にはしません。

勝つ側は勝利まで最短、負ける側は敗北まで最長の手を選びます。手数は双方を合わせた攻撃回数で、終局が0手。引き分けには有限の終局手数はありません。各合法手の評価は、指す前のプレイヤーを基準に表示します。

完全解析の上限は60,000状態または1,800ms。超過時は保守的に全体・各手を「未解析」と表示し、手数や必勝手を断定しません。上限は実行環境によって完了範囲が異なります。大きな全設定の完全解析を保証しません。

CPU初級はランダム。中級は即勝ち、相手の即勝ち回避を優先し、最大4手のネガマックス探索を使います（20,000探索節点または250msで打ち切り、生存手数差を評価）。最強は完全解析で勝ち・引き分け・負けの順に選び、勝ちは短く負けは長くします。上限に達すると中級相当へ切り替え、「上限到達・近似探索（未解析）」と表示します。近似探索の戦略的最適性は保証しません。

## 論文との照合

Antoine Dailly et al., [Simple Chopsticks: Playing with any number of hands and fingers, arXiv:2406.09083v1](https://arxiv.org/html/2406.09083v1)。Definition 1の加算・n超過時の除去・分配なしは本アプリのCutoffと一致します。論文の除去済みの手は、アプリでは0のカードとして保持し、合法手から除外します。Moduloは論文の主定理の対象ではありません。

n=2は命題1〜3の分類を、1〜6手の全正規化非終局局面について両手番で検証します。n=3は命題4の同数・全手1の先手必勝を1〜6手で検証します。

終局規約には注意が必要です。論文は片側の手が空なら双方が着手不能という組合せゲームの規約を使います。本アプリは要求仕様どおり、残った手のあるプレイヤーを勝者とします。通常プレイで最後の手を消した直後の敗者手番では一致します。論文分類テストは非終局から開始し、この規約差のある任意終局は対象外です。

## UI・操作性の改善

数値設定はすべて「− / 数値 / ＋」です。ボタンは44×46px以上。数値をタップして直接入力でき、キーボードにも対応します。入力途中の空欄や範囲外の値は確定時（フォーカス移動・変更確定）に整数・範囲内へ補正します。n・ルール変更時は各手の値も調整します。手数の＋は末尾に初期値1の手を追加し、−は末尾の手を削除します。各手のカード内で初期値を独立に変更できます。

CPUの攻撃は、青の「↗ 攻撃元」、オレンジの「◎ 攻撃先」、黄色の「✦ 変化」、通常表示への復帰の順で進みます。攻撃内容は演出開始から固定し、数字の変化と同時に計算結果を表示します。0になった手は「✕ 消滅」を経てグレーになります。色に加えて枠線・アイコン・文字で区別します。攻撃元の値は変わりません。

対戦画面の「攻撃演出の速さ」で、ゆっくり約3秒・標準約2秒（初期値）・速い約0.8秒を選べます。変更は次のCPU攻撃から適用します。CPUの計算時間とは別で、思考のための人工的な待ち時間は設けていません。人間の攻撃は同じ配色で約0.32秒の短い演出です。相手の攻撃可能な手を点線で示し、選択済みの自分の手をもう一度タップすると選択を解除できます。

演出中はカードの操作をロックします。数字の変化段階で内部局面・表示・棋譜を一度だけ更新し、演出終了時に次の手番を表示します。計算式は終了後も残ります。Undo・「もう一度」・画面切替は待機タイマーとWorkerを中断し、世代番号で古い非同期結果を無効にします。変化前の中断ではその攻撃は未確定、変化後は棋譜に記録済みとなり、Undoは従来の規則で戻します。

「もう一度」は従来のリセットを改名した機能で、初期局面・先手・人間の担当・相手・CPU難易度を維持し、盤面と棋譜を初期化します。演出速度も維持します。CPU先手なら再度CPUが攻撃します。

対戦中に必勝手を自動表示する機能は追加していません。局面解析は設定画面で自分から開く形式を維持しています。動きを減らすOS設定では拡大・消滅のCSSアニメーションを抑え、段階表示と文字は維持します。


## 画面遷移とCPUメッセージ

対戦画面上部、手番表示のすぐ上に「← ルール設定に戻る」を配置しています。設定へ戻ってもルール、n、手数、各手の初期値、先手、対戦形式、人間の担当、CPU難易度を保持します。CPUの思考・演出中でも既存の中断処理を通るため、古い処理が戻った画面へ反映されることはありません。対戦開始・設定への復帰時は各画面の先頭を表示します。「もう一度」は引き続き同じ初期局面から再挑戦する操作です。

手番見出し、操作説明、攻撃内容の3領域を分けています。CPUの思考・攻撃中は見出しを「CPUの手番」、操作説明を「CPUの攻撃を見守ってください。」に保ちます。思考状況は攻撃内容欄だけに表示します。攻撃内容は攻撃元・対象の値とカード番号を最初から最後まで表示し、段階ごとの短い説明への書き換えは行いません。数字の変化時に計算式を加え、終了後も次の攻撃まで残します。各領域に高さを確保し、CPUの段階切替による盤面の上下移動を抑えています。


## ルール表示と独立した数学的検証

対戦画面は手番の右に「Modulo型」「Cutoff型」、n、簡単な消滅条件を表示する角丸パネルを備えます。対戦中のルール変更はできません。

`tests/independent.test.js` と `tests/helpers/independent.js` は、製品の遷移・正規化・解析を使わずに、カード順を区別した全有効局面を同期的不動点反復で評価します。Moduloはn=2〜5・両者1〜2手、Cutoffはn=2〜3・両者1〜2手を検証。計4,000局面の勝敗・終局手数、7,622合法遷移、3,296非終局での最強CPU選択が一致しました。勝ち・負け・引き分けの子局面条件と、探索上限時の未解析も確認します。既存の論文照合テストも維持しています。

実行は従来どおり `node --test`。ケース別の状態数、標準初期局面からの到達数、一致・不一致件数、検証範囲の限界はTEST_RESULTS.mdを参照してください。


## 共通GASアクセスカウンター

`access-counter.js` をdeferで1回読み込み、既存教材と共通のGASへ `app=chopsticks-game` としてGET送信します。参照したローカル教材はpenrose-tiling-challenge（送信実装）とstat-golf（共通URLの参照fixture）です。unit-circle-trigとallowance-labはローカルにありませんでした。

送信オプションは参照実装と同じ `method: 'GET'`、`mode: 'no-cors'`、`cache: 'no-store'`、`credentials: 'omit'`、`keepalive: true`。応答・本文は待たず、ゲームの動作に依存させません。カウンタースクリプトは操作イベントに接続せず、開始・設定変更・CPU・Undo・再挑戦・局面解析・画面切替では送信しません。同じページでスクリプトが再実行されても送信済みフラグで抑止します。ページを再読み込みすると新しい1回として送信します。

通信拒否・同期例外・fetch未対応でも無視し、再送・画面表示・エラーログ出力を行いません。GAS本体と他のリポジトリは変更していません。

テストは `node --test`。`tests/access-counter.test.js` はfetchを全件モックし、実際のGASに送信せず、実ui.jsのイベントハンドラーを最小DOM・仮想時計・Workerモックで実行します。カウンター導入後の通常ページをブラウザで読み込むと実送信になるため、検証目的の実ページ再読込は行っていません。
